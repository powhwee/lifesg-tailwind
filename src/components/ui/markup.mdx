# Markup

## Overview

Renders CMS-authored HTML with the LifeSG typography scale. Tag-level
styles flow from the design system; consumers can override the baseline
text size and colour per call.

## Import

<Source
  language="tsx"
  code={`import { Markup } from "@/components/ui/markup";

<Markup dangerouslySetInnerHTML={{ __html: cmsHtml }} />`}
/>

## Variants

### With base text size

`baseTextSize="sm"` (or `bl` / `md` / `xs`) applies the matching body
scale to the whole block instead of inheriting from the parent. Use
when CMS content lands in a context whose inherited typography doesn't
suit it — e.g. compact sidebars or footnote regions.

<Canvas of={MarkupStories.WithBaseTextSize} />

### With base text color

`baseTextColor` tints the baseline text colour for the whole block.
Use for de-emphasised or themed surfaces; tag-level colours (links,
headings) still come from the design system.

<Canvas of={MarkupStories.WithBaseTextColor} />

### Inline

`inline` renders a `<span>` wrapper instead of a `<div>` so a fragment
of CMS-formatted text can sit mid-sentence within surrounding copy.

<Canvas of={MarkupStories.Inline} />

## Accessibility

- `Markup` renders raw HTML — sanitize on the server before passing it
  in. Treat the input as untrusted unless it originates from a system
  you control.
- The component does not impose a heading hierarchy. If the CMS content
  starts at `<h2>`, ensure the surrounding page already has an `<h1>`.

## Notes

- When `baseTextSize` is omitted, typography is inherited from the
  parent — mirrors LifeSG's behaviour where `Markup` only applies
  typography when explicitly told to.
- `baseTextSize` accepts the body scale tokens: `bl`, `md`, `sm`, `xs`.
  Each maps to the matching `--typography-body-*` size / line-height /
  letter-spacing trio.
- `inline` switches the wrapper from `<div>` to `<span>` — useful when
  CMS-formatted text needs to stay on the same line as surrounding
  copy.
- Tag-level styles live in `globals.css` under `.markup-root` — that is
  where to adjust how `h1`, `h2`, `ul`, `a`, etc. render inside the
  Markup wrapper.
