# FullscreenImageCarousel

## Overview

Modal-presented full-screen image viewer. Supports keyboard navigation
(arrow keys), zoom, thumbnails, optional delete, and a `custom` item
type for non-image content (PDF previews, embedded documents, etc.).

## Import

<Source
  language="tsx"
  code={`import { FullscreenImageCarousel } from "@/components/ui/fullscreen-image-carousel";

<FullscreenImageCarousel
  show={open}
  items={[
    { src: "/photo.jpg", alt: "…", fileName: "photo.jpg", fileSize: "248 KB" },
  ]}
  onClose={() => setOpen(false)}
/>`}
/>

## Variants

### Starting mid-gallery

`initialActiveItemIndex` opens the carousel on a specific item instead
of the first — use when the user tapped a particular thumbnail in the
page underneath.

<Canvas of={FicStories.StartingMidGallery} />

### Hidden thumbnails

`hideThumbnail` drops the thumbnail strip along the bottom. Use for
single-image viewers or when vertical space for the main image matters
more than quick jumping.

<Canvas of={FicStories.HideThumbnails} />

### Hidden counter

`hideCounter` removes the "n of total" indicator — sensible when the
thumbnail strip already communicates position.

<Canvas of={FicStories.HideCounter} />

### Hidden magnifier

`hideMagnifier` removes the zoom controls for content where zooming
adds nothing (e.g. small or low-resolution images).

<Canvas of={FicStories.HideMagnifier} />

## Interactive

### With delete

Pass `onDelete` to surface a delete button in the chrome — the parent
owns the item array and removes the entry. Typical for upload-review
flows.

<Canvas of={FicStories.WithDelete} />

### Custom content

`type: "custom"` items render arbitrary content via `renderContent`
instead of an image — use when the carousel doubles as a generic file
viewer (PDF previews, documents).

## Accessibility

- Wrapped in a `Modal` (Base UI `Dialog`) so focus traps inside the
  carousel and Esc closes it.
- The modal's `aria-label` is set to "`{itemType} {n} of {total}`" so
  the screen reader announces position on open.
- Arrow keys (←/→) move between items globally while the carousel is
  open — attached at the document with capture so they take precedence
  over focus-element handlers.
- Each chrome button (zoom, delete, close, prev/next) has an explicit
  `aria-label`; thumbnails carry `aria-current="true"` for the active
  one.

## Notes

- Token namespaces: `--fic-backdrop`, `--fic-text`,
  `--fic-button-bg{,-hover}`, `--fic-icon`,
  `--fic-thumb-border{,-active}`.
- `items` is a discriminated union: `{ type: "image", src, alt? }` or
  `{ type: "custom", renderContent, thumbnailSrc?, itemLabel? }`.
  `type` defaults to `image` so existing image arrays don't need to be
  reshaped.
- `initialActiveItemIndex` only reads on `show` going true; changing
  it while the carousel is already open won't jump indexes — use the
  imperative ref's `setCurrentItem` for that.
- The forwarded ref exposes `{ currentItemIndex, setCurrentItem,
  goToPrevItem, goToNextItem }` for parents that need to drive it
  imperatively (e.g. external prev/next buttons).
