# Field

## Overview

Low-level field composition kit. Thin wrapper around Base UI's `Field`
primitives — `Field`, `FieldLabel`, `FieldDescription`, `FieldError`,
`FieldControl`, `FieldValidity` — styled with LifeSG field tokens.
Use this when you need full control over field layout; for the standard
label + description + error pattern, prefer `FormField`.

## Variants

### With description

Place a `FieldDescription` between the label and the control to surface
formatting hints or constraints. Base UI wires it into the control's
`aria-describedby` automatically.

<Canvas of={FieldStories.WithDescription} />

### With error

Set `invalid` on the `Field` root and render a `FieldError` after the
control. Use when validation fails and the user needs an inline,
field-scoped explanation rather than a page-level alert.

<Canvas of={FieldStories.WithError} />

### Disabled

Set `disabled` on the `Field` root to grey out the label and hide the
description (`FieldDescription` is hidden for disabled fields so screen
readers don't announce instructions for an unreachable control).

<Canvas of={FieldStories.Disabled} />

## Accessibility

- Base UI wires up label-to-control association and validation state
  automatically when the parts are nested inside `Field`. The control
  receives the right `aria-invalid` / `aria-describedby` references
  without manual ID plumbing.
- `FieldDescription` becomes the input's accessible description; it is
  hidden via `data-[disabled]:hidden` when the field is disabled, so
  screen readers don't announce instructions for a control they cannot
  reach.
- `FieldError` carries a `CircleAlert` icon by default; pass `hideIcon`
  if the surrounding layout already conveys the error state visually.

## Notes

- Token namespace: `--field-*` (label/description/error sizes,
  line-heights, and colours). The composite components in the stories
  use the existing `--input-*` tokens for the control surface.
- Pair with `FieldControl` for the actual input element; it is just a
  re-export of Base UI's `Field.Control` and accepts any input props.
- For typical forms, reach for `FormField` (one element, label +
  description + error in the right order) instead of composing these
  parts by hand.
