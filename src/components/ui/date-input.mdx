# DateInput

## Overview

Three-segment text input (DD / MM / YYYY) paired with a Popover-mounted
Calendar. Auto-advances between segments as you type; Backspace at an
empty segment moves focus back. Values are ISO `YYYY-MM-DD` strings.

## Import

<Source
  language="tsx"
  code={`import { DateInput, FormDateInput } from "@/components/ui/date-input";

const [value, setValue] = React.useState("");

<DateInput value={value} onChange={setValue} />`}

## Variants

### Pre-filled

Pass an ISO `YYYY-MM-DD` string as `value` to render the field already
populated — the segments and the popover calendar both reflect it. Use
when editing an existing record rather than capturing a new date.

<Canvas of={DateInputStories.PreFilled} />

### With min / max date

`minDate` and `maxDate` propagate to the popover calendar, clamping the
selectable window. Use for fields like appointment dates where only a
known range is valid.

<Canvas of={DateInputStories.WithMinMax} />

### With disabled dates

Pass an array of ISO strings to `disabledDates` to block specific days
(holidays, fully-booked slots) while leaving the rest of the window
selectable.

<Canvas of={DateInputStories.WithDisabledDates} />

### With Done button

`withButton` switches the popover calendar to a Cancel + Done flow —
picking a day doesn't fire `onChange` until Done is pressed. Use when
committing a date is expensive (triggers a fetch, clears dependent
fields).

<Canvas of={DateInputStories.WithDoneButton} />

## States

### Error

Set `error` to render the red error border. The bare `DateInput` shows
only the visual state — pair it with your own message, or use
`FormDateInput` for the standard wiring.

<Canvas of={DateInputStories.ErrorState} />

### Disabled

`disabled` greys out all three segments and blocks the calendar

## Accessibility

- Each segment is a real `<input>` with `aria-label` ("Day" / "Month"
  / "Year"), `inputMode="numeric"`, and `maxLength` matching the
  expected digit count.
- Focus auto-advances when a segment fills; Backspace at an empty
  segment moves focus to the previous segment for natural correction.
- The Popover calendar is anchored to the segment container; opening
  it doesn't steal focus from the typing flow.
- `name` (if provided) renders a hidden input carrying the composed
  ISO value so the segmented inputs play nicely with `<form>` submit.

## Notes

- `withButton` switches the calendar to a Cancel + Done flow — picks
  in the calendar don't fire `onChange` until Done is pressed.
  Useful when picking a date is an expensive commit.
- `minDate` / `maxDate` / `disabledDates` propagate to the Calendar
  inside the Popover.
- For the standard label + description + error wrapping, use
  `FormDateInput` — it carries `reserveErrorSlot` by default so the
  layout doesn't shift when an error appears.
- Token namespace: shared `--input-*` for shell, `--calendar-*` for
  the popover content.
