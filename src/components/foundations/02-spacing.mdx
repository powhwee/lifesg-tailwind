# Spacing

LifeSG ships a fixed spacing scale at `--lifesg-spacing-{N}` where N is
the value in pixels. The L3 component tokens reference these scale
values rather than raw pixels, so a single change at the L1 layer
ripples across every component padding.

## Tailwind scale

The Tailwind 4 `@theme inline` block maps a parallel
`--spacing-{component-token}` namespace so utilities like
`pt-card-padding-y` work directly. Component padding tokens live in
the L3 token files (e.g. `--card-padding-y`,
`--input-padding-x`) and surface as Tailwind utilities via the
`--spacing-*` shim.

<Source
  language="tsx"
  code={`/* Direct L1 scale — fine for one-off layout adjustments. */
<div style={{ padding: "var(--lifesg-spacing-16)" }} />

/* L3 component token via Tailwind — preferred for component chrome. */
<div className="px-card-padding-x py-card-padding-y" />`}
/>

## Notes

- The scale is **not** a continuous 4 px step — values skip past 24
  (next is 32, not 28) and 48 (next is 64). This is intentional and
  matches LifeSG's published scale.
- For one-off micro-pixel adjustments outside the scale (e.g.
  `outline-offset: -2px` to inset a focus ring), use a raw arbitrary
  Tailwind value (`outline-offset-[-2px]`) and note the reason —
  not every value needs to be a token.
