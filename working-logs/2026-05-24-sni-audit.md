## Cross-cutting findings

### Border-radius systemic drift

Almost all our S&I components use `rounded-md` (6.4px from Tailwind). LifeSG uses **4px** consistently. Components affected: Toggle, Filter, DateNavigator. (OTP already has its own `--otp-cell-radius: 0.25rem` = 4px — gives the right answer.)

### Touch-target by coincidence, not convention

Heights of 48 (input, button-default, pagination), 40 (date-navigator arrow, icon-button small, breadcrumb item) recur across components but are never tokenized. New `--touch-target-*` token will collapse this.

### Hardcoded widths

`w-72` (Filter), `min-w-[12rem]` (DateNavigator date span) hardcoded as Tailwind arbitrary values, not derived from intent. Filter should be intrinsic; DateNavigator's date span needs a wider min to prevent the LifeSG-equivalent display from looking cramped.

## Conventions to introduce

### 1. `--touch-target-*` token

```css
--touch-target-default: 3rem;     /* 48px — input, button-default, IconButton-default, pagination */
--touch-target-compact: 2.5rem;   /* 40px — IconButton-small, date-navigator arrow, breadcrumb, accordion */
```

Register as `--spacing-touch-target-default` / `--spacing-touch-target-compact` in `@theme inline` so utilities `h-touch-target-default`, `size-touch-target-default` work.

Apply to:
- `pagination.tsx`: `size-12` → `size-touch-target-default`, `min-w-12 h-12` → `min-w-touch-target-default h-touch-target-default`
- `date-navigator.tsx`: `size-10` arrow → `size-touch-target-compact`, `h-10` date display → `h-touch-target-compact`
- `breadcrumb.tsx`: existing `h-10` → `h-touch-target-compact`

(Defer Button + Input migration to a follow-up — touch the smallest surface first.)

### 2. `--component-radius` token (LifeSG 4px)

```css
--component-radius: 0.25rem;    /* 4px — LifeSG default; replaces rounded-md/rounded-lg in component chrome */
```

Apply to Toggle, Filter, DateNavigator (replacing `rounded-md`).

(OTP already at 4px via `--otp-cell-radius`. ImageButton stays at `rounded-lg` 8px — already matches LifeSG.)

### 3. `--toggle-py / --toggle-px` (toggle inner padding)

```css
--toggle-py: 0.75rem;    /* 12px — keeps our current rhythm */
--toggle-px: 1rem;       /* 16px — matches LifeSG horizontal padding */
```

Drop `p-3` (uniform 12px) → `py-toggle-py px-toggle-px`. Net effect: horizontal padding +4px, vertical unchanged. Closer to LifeSG's 11/16/8/16.

### 4. FeedbackRating responsive layout

Add Tailwind responsive direction: `flex-col md:flex-row`. Add horizontal padding when row (`md:px-12`). Drop `w-full` on Submit button — let intrinsic width. This restores LifeSG's compact desktop layout while keeping mobile column.

### 5. `--filter-min-width` (replaces hardcoded `w-72`)

```css
--filter-min-width: 11.5rem;    /* 184px — matches LifeSG intrinsic measurement */
```

Drop `w-72` from Filter aside, add `min-w-filter-min-width`. Let intrinsic content drive overall width up to consumer override.

### 6. `--date-navigator-date-min-width` (date span)

```css
--date-navigator-date-min-width: 18rem;    /* 288px — accommodates "12 May 2026, Tuesday" without ellipsis */
```

Replace `min-w-[12rem]` (192px) with this token. LifeSG measures ~370px for the date span (492 − 40 − 40 − gaps); 288 is a reasonable middle that fits long dates without going full-LifeSG.

### 7. Filter title typography

Switch Filter header from `text-component-header` (22/28) → `text-component-header-compact` (18/26). The existing component-body / header-compact convention already covers this — it's an application fix, not a new convention. LifeSG's Filter uses HeadingXS, which compact tokens match.
