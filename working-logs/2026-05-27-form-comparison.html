Job Application Form — Full Code Comparison

Every file a developer writes, shown side by side. Same feature, same visual output.

1. Root Layout — app/layout.tsx

LifeSG v3.x / v4 app/layout.tsx
// app/layout.tsx
import { LifeSGProviderWrapper } from "@/components/lifesg-provider-wrapper";

export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <body>
        <LifeSGProviderWrapper>
          {children}
        </LifeSGProviderWrapper>
      </body>
    </html>
  );
}
Tailwind Port app/layout.tsx
// app/layout.tsx
import { Navbar } from "@/components/ui/navbar";
import { Footer } from "@/components/ui/footer";
import "@/styles/globals.css";

export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <body>
        <Navbar title="CareerNav" items={[...]} />
        <main>{children}</main>
        <Footer links={[...]} />
      </body>
    </html>
  );
}
Difference: LifeSG needs a 'use client' provider wrapper for ThemeProvider. The Tailwind port puts Navbar and Footer directly in the server layout — no provider, no client boundary. The Navbar/Footer code that LifeSG puts in application-form.tsx (below) lives here instead.

2. Provider Wrapper — LifeSG only

3. Page Component — app/jobs/[id]/apply/page.tsx

LifeSG v3.x / v4 page.tsx — Server Component
// app/jobs/[id]/apply/page.tsx
import { ApplicationForm } from "@/components/jobs/application-form";
import { getJobDetails } from "@/lib/api";

export default async function ApplyPage({ params }) {
  const job = await getJobDetails(params.id);

  // Hands off ALL rendering to client component
  return <ApplicationForm job={job} />;
}
Tailwind Port page.tsx — Server Component
// app/jobs/[id]/apply/page.tsx
import { getJobDetails } from "@/lib/api";
import { Content, Section } from "@/components/ui/layout";
import { Typography } from "@/components/ui/typography";
import { ApplicationForm } from "./application-form";

export default async function ApplyPage({ params }) {
  const job = await getJobDetails(params.id);

  return (
    <Content>
      <Section>
        {/* Static headings — server-rendered HTML */}
        <Typography as="h1">Apply for {job.title}</Typography>
        <Typography as="p">at {job.company}</Typography>

        {/* Only the form is a client component */}
        <ApplicationForm job={job} />
      </Section>
    </Content>
  );
}
Difference: The LifeSG page.tsx is a thin pass-through — it fetches data then delegates everything to a client component. The Tailwind port page.tsx renders the layout wrappers and headings directly as server HTML, passing only the interactive form to the client.

What moved out of this file: In the Tailwind port, Navbar (~7 lines) and Footer (~6 lines) moved to layout.tsx. Layout wrappers and headings (~8 lines) moved to page.tsx. The form and modal code is the same length in both — the total code the developer writes is roughly equal, just distributed across server and client files differently.
